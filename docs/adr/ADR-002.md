# ADR-002: Migrasi Parsing Job Description ke AI-Based Extraction

* **Status:** Proposed
* **Date:** 2026-07-16

## Context
Jelaskan masalah atau kondisi yang mendorong keputusan ini.

Kondisi sekarang, data yang didapat dari scraping job ini, masih terbatas lebih ke arah alerting pengumuman lowongan kerja untuk konsumsi. Disini saya ingin mengembangkan lebih jauh dari sekedar alerting, menjadi data yang bisa diolah lebih lanjut, misal untuk analisis tren lowongan kerja serta insight terkait skill yang dibutuhkan di pasar kerja. Untuk itu, saya ingin menambahkan konten job description yang lebih lengkap, seperti salary, job seniority, job type, dan lain-lain. Sehingga data yang dihasilkan dari scraping job ini bisa lebih bermanfaat untuk analisis lebih lanjut.

## Options Considered
Opsi-opsi yang dipertimbangkan beserta alasan singkat.

1. **Opsi A** — Kelebihan & kekurangan
Menambahkan atribut job lain seperti salary, job seniority, job type, skillset, dan lain-lain. Data-data tersebut direncanakan untuk diparse menggunakan model AI SLM (Small Language Model) yang sudah ada untuk mengekstrak informasi yang relevan dari job description. 

Kelebihan dari opsi ini adalah proses parsing data bisa lebih akurat dan relevan karena menggunakan model AI yang sudah terlatih untuk memahami konteks bahasa. 

Kekurangannya adalah membutuhkan biaya setiap menjalankan model tersebut melalui API pihak ketiga, tetapi karena skala data yang diambil tidak terlalu besar, biaya ini masih bisa ditoleransi, terutama jika menggunakan model small dan cost-to-performance ratio yang tinggi seperti DeepSeek.

2. **Opsi B** — Kelebihan & kekurangan
Seperti opsi A, tetapi parsing dilakukan menggunakan hierarki fallback yakni pertama dengan rule based parsing, jika tidak berhasil, maka menggunakan fuzzy matching, dan jika masih tidak berhasil, baru menggunakan model AI SLM.

Kelebihan dari opsi ini adalah biaya parsing data bisa lebih murah karena sebagian besar data bisa diparse menggunakan rule based parsing, sehingga hanya sebagian kecil data yang membutuhkan model AI.

Kekurangan dari opsi ini adalah proses parsing data bisa lebih lambat karena harus melalui beberapa tahap fallback, dan akurasi parsing data bisa lebih rendah dibandingkan menggunakan model AI secara langsung, terutama untuk job description yang kompleks atau ambigu.

## Decision
Keputusan yang diambil dan alasan logisnya.

- **Pilihan final:** Opsi A
- **Kenapa opsi ini dipilih (bukan yang lain):**
Karena opsi A memberikan akurasi parsing data yang lebih tinggi, sehingga data yang dihasilkan lebih relevan dan bermanfaat untuk analisis tren lowongan kerja dan insight terkait skill yang dibutuhkan di pasar kerja. Juga berbagai atribut data yang relevan bisa sekalian diambil langsung dalam sekali panggil berdasarkan job description sehingga proses scraping job bisa lebih efisien.

- **Detail implementasi jika relevan:**
    - Atribut job complete (termasuk yang sudah ada sebelumnya) semuanya akan langsung diparsing dengan AI instead of mengandalkan tag scraping seperti sekarang. Kenapa? karena struktur halaman job bisa berubah sehingga kode scraping bisa rusak suatu saat. Dengan menggunakan model AI, parsing job description bisa lebih fleksibel dan adaptif terhadap perubahan struktur halaman job.
    
    Atribut yang diekstrak:
    ```json
    {
      "title": "Data Engineer Intern",
      "company": "PT Tech Inovasi",
      "location": "Jakarta, Indonesia",
      "salary_min": 5000000,
      "salary_max": 8000000,
      "salary_currency": "IDR",
      "job_type": "full_time",        // enum: full_time / part_time / contract / internship / freelance
      "seniority": "intern",          // enum: intern / entry / mid / senior / lead / manager / executive
      "skills": ["python", "sql", "airflow"], // array of strings
      "posting_date": "2026-07-01",   // ISO 8601 format (YYYY-MM-DD)
      "link": "https://example.com/job/123"
    }
    ```

    - **Model yang digunakan: DeepSeek-V4-Flash**
        
        **Alasan pemilihan:**
        1. **Biaya sangat rendah:** Harga $0.14 per 1M input token dan $0.28 per 1M output token. Dengan estimasi 1.000 token input + 50 token output per panggilan, biaya per job hanya sekitar **Rp 2-3**.
        2. **Free quota:** Pengguna baru mendapatkan 5 juta token gratis (≈ 5.000 job descriptions tanpa biaya).
        3. **Kinerja:** Context length 1M token, cukup untuk menampung job description terpanjang sekalipun.
        4. **Output terstruktur:** Mendukung JSON mode untuk memastikan output selalu dalam format yang diinginkan.
        5. **Prompt caching:** Diskon 50× lebih murah untuk input yang berulang (cache hit) — ideal untuk instruksi sistem yang sama di setiap panggilan.
        6. **Kecepatan:** Latency rendah, cocok untuk pipeline scraping real-time.
        
        **Estimasi biaya operasional:**
        | Komponen | Harga per 1M token | Token per panggilan | Biaya per panggilan |
        |:---|:---|:---|:---|
        | Input (cache miss) | $0.14 | 1.000 | $0.00014 (≈ Rp 2,2) |
        | Output | $0.28 | 50 | $0.000014 (≈ Rp 0,22) |
        | **Total** | | | **$0.000154 (≈ Rp 2,4)** |
        
        **Fallback strategy:** Jika DeepSeek API tidak tersedia (timeout / rate limit / maintenance), raw job description akan disimpan dalam queue untuk diproses ulang di batch berikutnya. Tidak ada fallback ke model lain untuk menjaga konsistensi biaya dan output format.
        
        **Alternatif yang dipertimbangkan namun ditolak:**
        - *GPT-4o-mini:* Biaya 4-5× lebih mahal ($0.60/1M input) → tidak cost-effective.
        - *Phi-3-mini (self-hosted):* Membutuhkan infrastruktur GPU (~4-6GB VRAM) dan maintenance, tidak sebanding untuk skala data kecil.
        - *Qwen2.5-1.5B:* Performa ekstraksi informasi masih di bawah DeepSeek untuk teks bahasa campuran (Indonesia-Inggris) pada job description.

### Incremental Parsing — Skip Job yang Sudah Diparse

Pipeline berjalan setiap hari, tetapi sebagian besar job posting masih sama dengan hari sebelumnya. Agar tidak membayar AI parsing untuk data yang sama berulang kali:

1. **Hash-based dedup:** Setiap job yang berhasil diparse oleh AI akan menyimpan `sha256(job_description)` ke file manifest di S3 (`_parsed_jobs/`).
2. **Cek di awal pipeline:** Silver layer membaca daftar hash yang sudah diparse. Jika hash job description cocok → skip AI parsing, pakai data lama.
3. **Handle perubahan:** Jika deskripsi berubah (hash beda) → job dianggap "updated" → AI parse ulang.

**Dampak:** Hanya ~10-20% job per hari yang benar-benar butuh AI parsing (job baru atau deskripsi berubah). Biaya harian turun dari Rp 2.400 menjadi **~Rp 300-500**.

```
Scrape → Hash job_description → Cek di _parsed_jobs/
         ├── Hash cocok → Skip AI, pakai data silver lama
         └── Hash beda/baru → AI parse → simpan hash baru
```

### Impact ke Layer yang Ada

Penambahan field AI parsing berdampak ke beberapa layer:

| Layer | Dampak | Tindakan |
|-------|--------|----------|
| **Bronze** | Field `job_description` dipertahankan. Tidak ada perubahan skema. | ✅ Tidak perlu perubahan |
| **Silver** | Skema bertambah: `salary_min`, `salary_max`, `salary_currency`, `job_type`, `seniority`, `skills[]`, `posting_date` | Update schema validasi + Glue table |
| **Gold** | View Athena perlu tambahan kolom baru untuk query salary, skill trends | Update `v_jobscraper_clean` + `analytics_views.sql` |
| **Dashboard** | Chart tambahan: distribusi salary, skill demand trend, seniority breakdown | Tambah chart baru di Superset |
| **Data existing** | Ribuan job lama tidak punya field AI parsing → berarti null | Backfill opsional (bisa bertahap) |

## Consequences
Dampak dari keputusan ini — jujur soal trade-off.

* **Positif:**
  * **Keuntungan 1:** Pipeline semakin komprehensif dan upgrade dari sekedar alerting menjadi data yang bisa diolah lebih lanjut untuk analisis tren lowongan kerja dan insight terkait skill yang dibutuhkan di pasar kerja IT terutama.
  
  * **Keuntungan 2:** Penggunaan AI meningkatkan akurasi dan kemudahan parsing data dibandingkan mengandalkan rule based serta scraping berdasarkan tag HTML yang bisa berubah sewaktu-waktu.
  
  * **Keuntungan 3:** Resilience terhadap perubahan struktur HTML portal lowongan kerja. Tidak perlu maintenance kode scraping saat layout berubah.

* **Negatif:**
  * **Konsekuensi 1:** Menambah cost dalam pipeline karena harus memanggil API pihak ketiga untuk parsing job description menggunakan model AI SLM. Namun karena skala data yang diambil tidak terlalu besar (estimasi < 1.000 job/hari dengan total token < 1M/hari), biaya operasional harian hanya sekitar **Rp 2.400 - Rp 3.000**, masih sangat tolerabel.
  
  * **Konsekuensi 2:** Perlu adanya perubahan pada kode scraping untuk mengambil isi tag besar saja dan teks di-flatten menjadi satu blok plain text sebagai input ke model AI.
  
  * **Konsekuensi 3:** Dependency pada third-party API (DeepSeek). Jika API down atau terjadi perubahan pricing yang signifikan, perlu ada contingency plan (misal: self-hosted model atau migrasi ke provider lain).
  
  * **Konsekuensi 4:** Latency tambahan: setiap job membutuhkan 0.5-2 detik tambahan untuk panggil API. Untuk skala < 1.000 job/hari, total tambahan waktu masih acceptable (± 15-30 menit extra).
